# 热备

一台主机接受操作，一台备机持续拉主机的事件日志和密钥表，自己只读。主机坏了，由管理员把备机提升为主机。

**这不是 Raft，不会自动选主。** 没有第三方仲裁，两台机器互相连不上的时候，谁也无法知道对方是坏了还是只是连不上。所以切换由人决定，规则只有一条：确认旧主机已经停机，或者它还连得上（能被通知停下），再提升备机。

## 配置

主机（`acw.toml`）：

```toml
[standby]
peers = ["https://acw-b.internal:8787"]   # 备机的地址。主机每 5 秒看一眼：对端成了任期更高的主机，自己就停止接受操作
token_env = "ACW_REPLICA_TOKEN"            # 两台机器共用的复制令牌，放环境变量里
```

备机：

```toml
[standby]
primary = "https://acw-a.internal:8787"    # 主机的地址。数据目录是空的时候，配了它就以备机身份启动
peers = ["https://acw-a.internal:8787"]    # 提升以后，它也要留意旧主机
token_env = "ACW_REPLICA_TOKEN"
```

两台机器的其余配置（代码托管、沙箱、模型接入的环境变量）要一样，这样备机提升后能直接干活。备机的数据目录要从空的开始。

复制端点（`/replica/…`）会把整张密钥表（模型 key、成员令牌的哈希、任务的网关令牌）交给拿着复制令牌的人。把它们放在内网或 TLS 后面。

## 角色

一台机器是下面三种之一，记在它自己的数据库里。重启后以上次的角色为准，不看配置：提升过的备机重启后仍是主机，被取代的旧主机重启后仍是被取代的。

| 角色 | 能做什么 |
| --- | --- |
| 主机（primary） | 一切 |
| 备机（follower） | 只读：GET 请求照常，控制台能看；其它请求返回 503。不调度、不发通知 |
| 已被取代（fenced） | 同备机。它的日志可能比新主机多出几条没被复制走的事件，不能再当备机用 |

`GET /api/standby` 看这台的角色、任期、事件序号、落后多少条、上次同步时间和问题。控制台的“运维”页显示同样的内容；备机和被取代的机器在每一页顶上有一条只读提示。

## 切换

1. 确认主机的状态：停机了，或者还能访问。
2. 在备机上：`curl -X POST -H "Authorization: Bearer <管理员令牌>" https://acw-b.internal:8787/api/standby/promote`，或者在备机控制台的“运维”页点“提升为主机”。管理员的令牌在备机上有效，因为密钥表是复制过来的。
3. 看返回：

   ```json
   { "epoch": 2, "seq": 1234, "caught_up": true, "old_primary_fenced": true, "note": "旧主机已停止接受操作" }
   ```

   `caught_up` 为 false 表示提升前没能再从旧主机拉一次：旧主机最后那一小段还没复制过来的事件丢了。`old_primary_fenced` 为 false 表示没能通知到旧主机：确认它是停着的；它再启动时如果配了 `peers`，看到这台的任期更高会自己停下。
4. 把流量（域名、webhook 地址、沙箱访问模型网关的地址）指到新主机。
5. 旧主机要重新加入：清空它的数据目录，配上 `standby.primary` 指向新主机，启动。

## 切换后会怎样

备机有的：事件日志、全部投影、密钥表。备机没有的，以及后果：

| 没有复制的 | 后果 |
| --- | --- |
| 副作用队列 | 旧主机上排着还没发出去的通知不会再发；排着要销毁的沙箱没人销毁，要到沙箱主机上清理 |
| git 镜像 | 新主机第一次用到某个仓库时从远端重新拉。任务分支每次提交后都推到了远端，所以代码不丢 |
| 产物（命令的完整输出） | 留在旧主机上。时间线里的摘要在事件里，是有的 |
| 沙箱 | 在跑的任务会发现沙箱不在了，用任务分支重建一个，从当前阶段继续（和任何一次丢沙箱一样）。Worker 的会话存档在产物目录里，没有复制，所以是新会话 |
| 本地代码托管（演示用）的 PR 记录 | 只影响演示 |

## 日志分叉

备机每次拉取都带上自己最后一条事件的序号，主机返回那一条的指纹。对不上，说明两边的日志不是同一条（最常见的原因：把一台有自己历史的机器配成了备机，或者被取代的旧主机没清数据就当备机启动）。备机这时什么都不写，“运维”页和 `/api/standby` 的 `problem` 里会写明，处理办法是清空它的数据目录重新同步。

## 验证过什么，没验证什么

`crates/acw-engine/tests/standby.rs`：备机追平并持续跟随；只读（HTTP 和存储层两层都拒绝）；只有管理员能提升、只有备机能被提升；提升后任期加一、旧主机停止接受操作、新主机接着原来的编号开任务；有自己历史的机器当不了备机；主机看到更高的任期会自己停下。

没验证：两台真实机器之间；网络分区；大日志的首次同步耗时（每次拉 500 条，追平前每 10 毫秒拉一次）。
