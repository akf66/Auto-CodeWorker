# 状态表（v0.2，2026-11-14）

这是一个个人使用的项目，目标是自己用着顺手，不追求高并发、高可用和多租户安全。个人用法见 [`config/acw.personal.toml`](../config/acw.personal.toml)：本机目录当沙箱、真实 GitHub、codex 当 Worker。

“已测试”指有自动化测试覆盖并通过；“已写，未验证”指代码写完、测试只覆盖了能在开发环境里跑的部分，没有在真实环境里跑过。

v0.2 把 v0.1 “没有做”里的项目都过了一遍。大部分做完并有测试；有几项做成了比设计更简单的版本，下面逐项写明差在哪里；云沙箱没有写，原因见“没有做”。

另外修了一个 v0.1 就有的问题：两个任务同时对同一个仓库的镜像做 fetch 或打包会抢引用。现在每个镜像同一时间只有一个写入者（`GitGateway` 里的锁）。这是跨仓库的测试暴露出来的。

从 v0.1 升级：直接用 v0.2 打开 v0.1 的数据目录。试过一次：v0.1 的演示跑出一个等审批的 PR，换成 v0.2 启动，重建投影（重放 75 个事件）正常，新加的设置项取默认值，那个 PR 照常合并。

## 在真实环境里跑通过的（2026-11-14）

用 `config/acw.personal.toml` 这种配法：真实 codex CLI（0.162）、OrcaRouter 上的真实模型（路由和写测试用 `deepseek/deepseek-v4-flash`，开发和审查用 `deepseek/deepseek-v4-pro`，接口类型 Responses）、本机目录当沙箱、GitHub 上的一个私有测试仓库。

| 走通的事 | 结果 |
| --- | --- |
| 一条消息 → Router 整理需求单并开任务 | 项目、目标、验收标准都判断对了 |
| codex 经模型网关改代码（Responses 接口原样转发） | 改动正确，用量被网关记下 |
| 检查、审查、E2E、按验收标准生成测试 | 生成的测试在改动前失败、改动后通过 |
| 克隆私有仓库、推任务分支、开 PR | PR 正常开出 |
| 在 GitHub 上合并后，Engine 靠轮询发现并结束任务 | 正常 |

试跑暴露并修掉的三个问题：

- **验收测试被悄悄丢掉**：真实模型把验收标准序号写成字符串 `"1"`，原来的解析整体失败，结果是“0 个测试”也算通过。现在逐项解析、接受字符串数字；一个可用的测试都没有时在时间线上写明，并且不缓存，下次重试。审查发现的行号也同样放宽了。
- **PR 合并后又开了一个 PR**：在 GitHub 上合并（squash）后，Engine 先看到 main 前进、后看到 PR 已合并，于是把已经合并的分支变基并重新开了 PR。现在变基前和开 PR 前都会再查一次 PR 是否已合并。
- **飞书消息去重的键**：见 [feishu.md](feishu.md)。

这只是两个小任务，说明接线是通的，不说明模型在大仓库、难任务上的质量。

### 有意不做

个人项目用不到，不是待办。

| 设计里有的 | 为什么不做 |
| --- | --- |
| Raft / 自动选主 | 单机就够。真要高可用，已有的热备加人工切换也够；要自动切换应该加外部仲裁，而不是自己实现 Raft |

## 已知的限制

- 本地沙箱没有隔离，默认被拒绝使用，要在配置里写 `allow_unisolated = true` 才行。远程沙箱主机用的提供方没有隔离时，同样默认拒绝。不要用没有隔离的沙箱跑不可信的仓库。
- 密钥表是 SQLite 里的明文，靠文件权限保护。备机会把整张密钥表拉过去：复制端点要放在内网或 TLS 后面。
- 热备不复制副作用队列、git 镜像、产物和沙箱。切换后：旧主机上还没发出去的通知不会再发；镜像从远端重新拉；在跑的任务用任务分支重建沙箱后继续；旧的产物（日志）留在旧主机上。
- 被取代的旧主机不会自动变回备机：清空它的数据目录，配上 `standby.primary` 重新启动。
- 主机连不上对端时不会停：分区期间旧主机继续接受操作，直到它能看到对端为止。所以只在确认旧主机停机、或它还连得上时提升备机。
- 代码索引会误认和漏认，所以它只用来“多认出”模块（多触发确认规则是安全的方向），不用来放行任何东西。
- 任何成员都能看到全部项目的任务列表和时间线；角色只限制能做什么。
- 模型价格要自己在设置里填。没填价格的模型金额按 0 计，预算对它不起作用，成本页会提示。
- 模型网关在客户端提前断开连接时，这一次请求的用量不会被记上。
- Worker 正在跑的时候发来的消息要等这一轮跑完才会被处理，不会打断当前这一轮。
- 性能证据在沙箱里测，机器忙的时候噪声大。判定用了噪声带，但它只能挡住明显的误判，不能替代专门的压测环境。

约 11,400 行 Rust（另有约 1,500 行测试），950 行控制台脚本，85 个自动化测试，另有一个用真实 codex CLI 的 PoC 测试。`cargo clippy --workspace --all-targets` 没有警告。
